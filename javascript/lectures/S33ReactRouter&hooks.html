Chapter 01
React Router를 왜 사용하는가

1. React는 기본적으로 한 페이지 안에서 동작한다

React 앱은 보통 하나의 index.html을 중심으로 동작하는 SPA 구조를 가진다.

브라우저가 처음 index.html 로드 ↓ React 실행 ↓ URL에 따라 다른 컴포넌트를 보여줌

그런데 URL이 바뀔 때 어떤 컴포넌트를 보여줄지 React 혼자 자동으로 결정하지는 않는다.

2. 라우터 없이 화면을 바꾸면 생기는 문제

state로 화면을 바꾸는 방식도 가능하다.

function App() {
    const [page, setPage] = useState("home");

    return (
        <div>
            <button onClick={() => setPage("home")}>홈</button>
            <button onClick={() => setPage("board")}>게시판</button>

            {page === "home" && <Home />}
            {page === "board" && <Board />}
        </div>
    );
}

하지만 이 방식은 주소창 URL이 바뀌지 않는다.

문제점
  • 주소를 복사해서 특정 페이지를 공유하기 어렵다.
  • 새로고침하면 현재 화면 상태가 사라질 수 있다.
  • 브라우저 뒤로가기, 앞으로가기를 자연스럽게 처리하기 어렵다.
  • 게시글 상세 페이지처럼 /board/3 형태의 주소를 만들기 어렵다.

3. Router의 역할

React Router는 URL과 컴포넌트를 연결해주는 도구이다.

/ → Home 컴포넌트 /about → About 컴포넌트 /board → BoardList 컴포넌트 /board/3 → BoardDetail 컴포넌트 /login → Login 컴포넌트
Router를 사용하는 이유
  • URL에 따라 다른 화면을 보여주기 위해
  • 새로고침해도 현재 URL에 맞는 화면을 보여주기 위해
  • 뒤로가기, 앞으로가기 등 브라우저 히스토리를 사용하기 위해
  • 상세 페이지, 검색 페이지처럼 주소에 데이터를 담기 위해
  • 공유 가능한 주소를 만들기 위해

Chapter 03
Routes, Route, Link

1. 기본 라우팅

Routes는 여러 개의 라우트 목록이고, Route는 URL 하나와 컴포넌트 하나를 연결한다.

import { Routes, Route, Link } from "react-router-dom";

function Home() {
    return <h1>Home</h1>;
}

function About() {
    return <h1>About</h1>;
}

function Board() {
    return <h1>Board</h1>;
}

function NotFound() {
    return <h1>404 페이지를 찾을 수 없습니다.</h1>;
}

export default function App() {
    return (
        <div>
            <nav>
                <Link to="/">홈</Link>
                <Link to="/about">소개</Link>
                <Link to="/board">게시판</Link>
            </nav>

            <Routes>
                <Route path="/" element={<Home />} />
                <Route path="/about" element={<About />} />
                <Route path="/board" element={<Board />} />
                <Route path="*" element={<NotFound />} />
            </Routes>
        </div>
    );
}

2. 각 요소의 역할

요소 역할
BrowserRouter 브라우저 주소창과 React Router를 연결한다.
Routes 여러 Route 중 현재 URL과 맞는 Route를 찾는다.
Route 특정 path일 때 어떤 element를 보여줄지 정한다.
Link 새로고침 없이 다른 URL로 이동한다.

3. a 태그 대신 Link를 쓰는 이유

일반 <a href="/board">는 브라우저가 새 페이지를 요청하게 만들 수 있다. React SPA에서는 새로고침 없이 컴포넌트만 바꾸고 싶기 때문에 Link를 사용한다.

  • a: 문서 이동, 새로고침 발생 가능
  • Link: React Router가 URL만 바꾸고 화면을 교체

4. NavLink

NavLink는 현재 URL과 일치하는 링크에 active 스타일을 줄 때 사용한다.

import { NavLink } from "react-router-dom";

function Header() {
    return (
        <nav>
            <NavLink to="/">홈</NavLink>
            <NavLink to="/board">게시판</NavLink>
            <NavLink to="/login">로그인</NavLink>
        </nav>
    );
}

Chapter 04
URL 파라미터와 useParams

1. URL 파라미터가 필요한 이유

게시글 상세 페이지처럼 ID에 따라 다른 데이터를 보여줘야 할 때 사용한다.

/board/1 → 1번 게시글 /board/2 → 2번 게시글 /board/3 → 3번 게시글

2. Route 설정

<Routes>
    <Route path="/board" element={<BoardList />} />
    <Route path="/board/:id" element={<BoardDetail />} />
</Routes>

:id는 URL에서 바뀌는 값을 의미한다.

3. useParams로 값 꺼내기

import { useParams } from "react-router-dom";

function BoardDetail() {
    const { id } = useParams();

    return (
        <div>
            <h1>게시글 상세</h1>
            <p>게시글 번호: {id}</p>
        </div>
    );
}
useParams를 쓰는 이유

URL 경로 안에 들어있는 동적 값을 컴포넌트에서 사용하기 위해 쓴다.

Chapter 05
useNavigate

1. useNavigate가 필요한 이유

Link는 사용자가 클릭해서 이동할 때 좋다. 하지만 로그인 성공 후 이동, 등록 완료 후 목록으로 이동처럼 코드 안에서 페이지를 이동해야 할 때는 useNavigate를 사용한다.

import { useNavigate } from "react-router-dom";

function Login() {
    const navigate = useNavigate();

    function handleLogin() {
        // 로그인 성공 후 메인 페이지로 이동
        navigate("/");
    }

    return (
        <button onClick={handleLogin}>
            로그인
        </button>
    );
}

2. 자주 쓰는 상황

  • 로그인 성공 후 메인으로 이동
  • 게시글 등록 후 상세 페이지로 이동
  • 삭제 완료 후 목록으로 이동
  • 뒤로가기 버튼 구현
navigate("/board") → /board로 이동 navigate("/") → 홈으로 이동 navigate(-1) → 이전 페이지로 이동

Chapter 06
useSearchParams

1. Query String이란?

URL 뒤에 붙는 검색 조건이다.

/board?keyword=react /search?category=book&page=2 /products?sort=price

목록 검색, 필터, 정렬, 페이지 번호처럼 “화면 상태를 URL에 남기고 싶을 때” 사용한다.

2. useSearchParams 예제

import { useSearchParams } from "react-router-dom";

function BoardList() {
    const [searchParams, setSearchParams] = useSearchParams();

    const keyword = searchParams.get("keyword") || "";

    function handleSearch() {
        setSearchParams({ keyword: "react" });
    }

    return (
        <div>
            <h1>게시판</h1>
            <p>검색어: {keyword}</p>

            <button onClick={handleSearch}>
                react 검색
            </button>
        </div>
    );
}
useSearchParams를 쓰는 이유
  • 검색어, 정렬, 필터 값을 URL에 저장할 수 있다.
  • 사용자가 현재 검색 결과 URL을 공유할 수 있다.
  • 새로고침해도 검색 조건이 주소에 남아 있다.

Chapter 07
중첩 라우팅과 Outlet

1. 중첩 라우팅이 필요한 이유

여러 페이지가 공통 레이아웃을 공유하는 경우가 많다.

공통 영역: Header Sidebar Footer 바뀌는 영역: Home Profile Settings Board

공통 레이아웃은 유지하고, 내부 내용만 URL에 따라 바꾸고 싶을 때 중첩 라우팅을 사용한다.

2. Outlet 예제

import { Routes, Route, Link, Outlet } from "react-router-dom";

function Layout() {
    return (
        <div>
            <header>
                <Link to="/">홈</Link>
                <Link to="/mypage">마이페이지</Link>
            </header>

            <main>
                <Outlet />
            </main>
        </div>
    );
}

function MyPage() {
    return (
        <div>
            <h1>마이페이지</h1>
            <Link to="profile">프로필</Link>
            <Link to="settings">설정</Link>

            <Outlet />
        </div>
    );
}

function App() {
    return (
        <Routes>
            <Route path="/" element={<Layout />}>
                <Route index element={<Home />} />
                <Route path="mypage" element={<MyPage />}>
                    <Route path="profile" element={<Profile />} />
                    <Route path="settings" element={<Settings />} />
                </Route>
            </Route>
        </Routes>
    );
}

3. Outlet의 역할

Outlet은 자식 라우트가 렌더링될 자리이다.

부모 Route element └── <Outlet /> └── 자식 Route element가 여기에 들어옴

Chapter 08
Hook 전체 그림

props와 state를 배운 뒤에는 다음 질문들이 생긴다.

  • 렌더링 후 API 요청은 어디서 하지?
  • input DOM에 직접 focus를 주고 싶으면?
  • 무거운 계산을 매번 다시 하지 않게 하려면?
  • 자식 컴포넌트에 넘기는 함수를 매번 새로 만들지 않으려면?
  • props를 여러 단계로 계속 넘기기 싫으면?
  • state 변경 로직이 너무 복잡해지면?
  • 반복되는 Hook 로직을 재사용하고 싶으면?

이 문제들을 해결하기 위해 여러 Hook을 사용한다.

Hook 왜 사용하는가 대표 상황
useEffect 렌더링 이후 외부 시스템과 동기화하기 위해 API 요청, 이벤트 등록, 타이머
useRef 렌더링과 상관없는 값을 저장하거나 DOM을 참조하기 위해 input focus, timer id, 이전 값 저장
useMemo 계산 결과를 재사용하기 위해 무거운 필터링, 정렬, 계산
useCallback 함수 자체를 재사용하기 위해 memo된 자식에게 함수 props 전달
useContext 멀리 떨어진 컴포넌트에 값을 전달하기 위해 로그인 사용자, 테마, 언어 설정
useReducer 복잡한 state 변경 로직을 한곳에 모으기 위해 form, todo, 상태 전환이 많은 화면
Custom Hook 반복되는 Hook 로직을 재사용하기 위해 useInput, useFetch, useToggle
수업 포인트

Hook을 외우는 것보다 “이 Hook은 어떤 문제를 해결하기 위해 쓰는가?”를 먼저 설명한다.

Chapter 09
useEffect

1. 왜 사용하는가?

useEffect는 컴포넌트가 렌더링된 후 외부 시스템과 동기화할 때 사용한다.

React 내부: props, state, JSX, 렌더링 React 외부: 서버 API 브라우저 이벤트 타이머 localStorage 외부 라이브러리

외부 시스템과 연결하는 작업은 렌더링 중에 하지 않고, 렌더링 이후 useEffect에서 처리한다.

2. API 요청 예제

import { useEffect, useState } from "react";

function UserList() {
    const [users, setUsers] = useState([]);

    useEffect(() => {
        fetch("https://jsonplaceholder.typicode.com/users")
            .then((res) => res.json())
            .then((data) => {
                setUsers(data);
            });
    }, []);

    return (
        <div>
            <h1>사용자 목록</h1>

            {users.map((user) => (
                <p key={user.id}>{user.name}</p>
            ))}
        </div>
    );
}

3. cleanup이 필요한 경우

useEffect 안에서 타이머, 이벤트 리스너 같은 외부 작업을 등록하면, 컴포넌트가 사라질 때 정리 작업도 함께 해야 한다.

이 정리 작업을 cleanup이라고 부른다.

컴포넌트 렌더링 ↓ useEffect 실행 ↓ 타이머 등록 / 이벤트 등록 ↓ 컴포넌트 제거 ↓ cleanup 실행 ↓ 타이머 제거 / 이벤트 제거

1. cleanup이 필요한 이유

cleanup을 하지 않으면 컴포넌트가 화면에서 사라져도, 타이머나 이벤트가 계속 살아있을 수 있다.

문제 상황
  • 사용하지 않는 타이머가 계속 실행될 수 있다.
  • 이벤트 리스너가 계속 남아 메모리 누수가 발생할 수 있다.
  • 이미 제거된 컴포넌트의 state를 변경하려고 시도할 수 있다.

2. Timer 예제

import { useEffect, useState } from "react";

function Timer() {

const [count, setCount] = useState(0);

useEffect(() => {

    console.log("타이머 시작");

    const timerId = setInterval(() => {

        setCount((prev) => prev + 1);

    }, 1000);

    return () => {

        console.log("타이머 제거");

        clearInterval(timerId);
    };

}, []);

return <h1>{count}</h1>;
}

3. 코드 흐름

컴포넌트 처음 렌더링 ↓ useEffect 실행 ↓ setInterval 등록 ↓ 1초마다 count 증가 ↓ 컴포넌트 제거 ↓ return 안의 cleanup 실행 ↓ clearInterval(timerId) ↓ 타이머 종료

4. return 함수가 cleanup이다

useEffect 안에서 반환하는 함수가 cleanup 함수이다. 

return () => {

clearInterval(timerId);

};

즉 “나중에 정리할 작업”을 return으로 등록하는 것이다.

5. 언제 cleanup이 실행되는가?

상황 cleanup 실행 여부
컴포넌트 제거 실행됨
의존성 값 변경 후 effect 재실행 전 실행됨
처음 렌더링 직후 실행 안됨

6. 이벤트 리스너 cleanup 예제

useEffect(() => {

    function handleResize() {

        console.log(window.innerWidth);

    }

    window.addEventListener("resize", handleResize);

    return () => {

        window.removeEventListener("resize", handleResize);

    };

}, []);

이 예제는 브라우저 크기 변경 이벤트를 등록하고, 컴포넌트가 제거될 때 이벤트 리스너를 제거한다.

cleanup 핵심 정리
  • 타이머, 이벤트 리스너 같은 외부 작업은 cleanup이 필요하다.
  • useEffect의 return 함수가 cleanup 함수이다.
  • cleanup은 컴포넌트 제거 시 실행된다.
  • cleanup을 하지 않으면 메모리 누수나 불필요한 작업이 발생할 수 있다.

4. useEffect를 쓰지 않아도 되는 경우

state나 props로 바로 계산할 수 있는 값은 effect가 필요 없다.

// 굳이 useEffect를 쓸 필요가 없는 예
function Price({ price, count }) {
    const total = price * count;

    return <h1>{total}</h1>;
}
useEffect 핵심
  • 렌더링 이후 실행된다.
  • API, 타이머, 이벤트처럼 React 밖의 작업에 사용한다.
  • 의존성 배열 값이 바뀌면 다시 실행된다.
  • 정리할 작업이 있으면 cleanup 함수를 반환한다.
  • 단순 계산에는 useEffect를 쓰지 않는다.

Chapter 10
useRef

1. useRef란?

useRef는 렌더링과 상관없는 값을 저장하거나, 실제 DOM 요소를 참조할 때 사용하는 Hook이다.

State ↓ 값이 바뀌면 리렌더링 Ref ↓ 값이 바뀌어도 리렌더링 안함

즉 state는 화면에 보여줄 값을 저장할 때 사용하고, ref는 화면 렌더링과 직접 관계없는 값을 저장할 때 사용한다.

2. 기본 문법

const ref = useRef(초기값);

값은 ref.current에 저장된다. 

ref.current
중요

useRef는 값을 저장하지만, 값이 바뀌어도 React가 다시 렌더링하지 않는다.

3. 왜 state 대신 useRef를 사용하는가?

state는 값이 바뀌면 컴포넌트를 다시 실행한다.

state 변경 ↓ React가 상태 변경 감지 ↓ 컴포넌트 다시 실행 ↓ 리렌더링

하지만 어떤 값은 화면을 다시 그릴 필요가 없다.

예: 타이머 ID, 클릭 횟수, 로그 스크롤 위치, 이전 값 저장, DOM 요소 참조

이런 값은 useRef로 관리하면 불필요한 렌더링을 막을 수 있다.

4. 왜 전역변수를 사용하지 않는가?

초급자는 종종 이렇게 생각한다.

"렌더링과 상관없는 값이면 그냥 전역변수 쓰면 되는 거 아닌가?"

하지만 전역변수는 React 컴포넌트마다 따로 관리되지 않는다. 

let count = 0;

function Counter() {

    function increase() {

        count++;

        console.log(count);
    }

    return (
        <button onClick={increase}>
            증가
        </button>
    );
}

위 코드에서는 모든 Counter 컴포넌트가 같은 count를 공유한다.

Counter A ↓ 같은 count 사용 Counter B ↓ 같은 count 사용

반면 useRef는 컴포넌트마다 독립적인 값을 가진다. 

function Counter() {

    const countRef = useRef(0);

    function increase() {

        countRef.current++;

        console.log(countRef.current);
    }

    return (
        <button onClick={increase}>
            증가
        </button>
    );
}
Counter A ↓ 자기만의 ref Counter B ↓ 다른 ref
한 문장 정리

전역변수는 앱 전체가 공유하지만, useRef는 컴포넌트마다 독립적으로 값을 가진다.

5. DOM 참조 예제

useRef의 가장 대표적인 사용 방법은 DOM 요소를 직접 참조하는 것이다. 

import { useRef } from "react";

function InputFocus() {

    const inputRef = useRef(null);

    function focusInput() {

        inputRef.current.focus();
    }

    return (
        <div>

            <input ref={inputRef} />

            <button onClick={focusInput}>
                input 포커스
            </button>

        </div>
    );
}

동작 흐름

렌더링 ↓ input DOM 요소가 생성됨 ↓ inputRef.current에 input DOM 저장 ↓ 버튼 클릭 ↓ inputRef.current.focus() ↓ input에 포커스 이동

즉 useRef를 사용하면 실제 DOM 요소에 직접 접근할 수 있다.

6. 값 저장 예제

ref는 렌더링과 상관없는 값을 저장할 때도 사용한다. 

import { useRef, useState } from "react";

function RenderCount() {

    const [count, setCount] = useState(0);

    const clickCountRef = useRef(0);

    function handleClick() {

        clickCountRef.current += 1;

        console.log("클릭 횟수:", clickCountRef.current);

        setCount(count + 1);
    }

    return (
        <button onClick={handleClick}>
            화면 count: {count}
        </button>
    );
}

동작 흐름

버튼 클릭 ↓ clickCountRef.current 증가 ↓ 콘솔 출력 ↓ ref 값 변경 ↓ ref만 변경하면 리렌더링 안됨 setCount 실행 ↓ state 변경 ↓ 리렌더링

여기서 중요한 점은:

ref 변경 → 리렌더링 안됨 state 변경 → 리렌더링됨

7. useRef 핵심 정리

  • useRef는 렌더링과 상관없는 값을 저장한다.
  • ref.current에 값을 저장한다.
  • ref.current를 바꿔도 리렌더링되지 않는다.
  • DOM 요소 참조에 자주 사용한다.
  • 전역변수와 달리 컴포넌트마다 독립적인 값을 가진다.
  • 화면에 보여줄 값은 state로 관리한다.

Chapter 11
useMemo

1. useMemo란?

useMemo는 계산 결과를 기억해두고, 의존성 값이 바뀌지 않으면 이전 계산 결과를 재사용하는 Hook이다.

렌더링 발생 ↓ useMemo 계산 확인 ↓ 의존성 변경됨? ├─ YES → 다시 계산 └─ NO → 이전 결과 재사용

즉 useMemo는 “계산 결과 캐시”라고 이해하면 쉽다.

2. 왜 사용하는가?

React는 state가 변경되면 컴포넌트를 다시 실행한다.

state 변경 ↓ 컴포넌트 함수 다시 실행 ↓ 함수 안의 코드 다시 실행

이때 무거운 계산도 계속 다시 실행될 수 있다. 

function App({ products }) {

    const [count, setCount] = useState(0);

    const filtered = products.filter((product) => {

        console.log("상품 필터링");

        return product.price > 1000;
    });

    return (
        <div>

            <h1>{count}</h1>

            <button onClick={() => setCount(count + 1)}>
                증가
            </button>

        </div>
    );
}

위 코드에서는 count만 변경해도:

컴포넌트 다시 실행 ↓ products.filter() 다시 실행 ↓ 불필요한 계산 반복

products가 바뀌지 않았는데도 필터링을 계속 다시 하게 된다.

3. useMemo 사용

import { useMemo, useState } from "react";

function ProductList({ products }) {

    const [keyword, setKeyword] = useState("");

    const filteredProducts = useMemo(() => {

        console.log("상품 필터링 실행");

        return products.filter((product) =>
            product.name.includes(keyword)
        );

    }, [products, keyword]);

    return (
        <div>

            <input
                value={keyword}
                onChange={(e) => setKeyword(e.target.value)}
                placeholder="검색어"
            />

            {filteredProducts.map((product) => (
                <p key={product.id}>
                    {product.name}
                </p>
            ))}

        </div>
    );
}

4. useMemo 동작 흐름

처음 렌더링 ↓ useMemo 계산 실행 ↓ 결과 저장 다음 렌더링 ↓ products, keyword 변경 확인 ├─ 변경됨 → 다시 계산 └─ 변경 안됨 → 이전 결과 재사용

즉 useMemo는 컴포넌트 자체를 기억하는 것이 아니라, 계산 결과 값을 기억한다.

중요

useMemo는 “컴포넌트 캐시”가 아니라 “계산 결과 캐시”이다.

5. useMemo와 React.memo 차이

기능 설명
useMemo 계산 결과를 기억한다.
React.memo 컴포넌트 렌더링 자체를 건너뛴다.

6. useMemo를 왜 fetch에 사용하면 안되는가?

초급자는 종종 useMemo를 “의존성 배열이 있는 함수” 정도로 생각해서 fetch를 넣기도 한다. 

// 잘못된 사용
useMemo(() => {

    fetch("/api/users");

}, []);

하지만 useMemo는 계산 결과를 저장하기 위한 Hook이다.

fetch는 계산이 아니라 “외부 작업”이다.

useMemo ↓ 계산 결과 캐시 용도 fetch ↓ 서버 통신 ↓ 외부 작업 ↓ 부수효과(side effect)

React에서는 렌더링 과정과 외부 작업을 구분한다.

Hook 역할
useMemo 렌더링 중 계산 결과 저장
useEffect 렌더링 이후 외부 작업 처리

그래서 API 요청은 useEffect에서 처리한다. 

// 올바른 사용
useEffect(() => {

    fetch("/api/users")
        .then((res) => res.json())
        .then((data) => {

            console.log(data);

        });

}, []);

7. useMemo를 남용하면 안되는 이유

useMemo도 내부적으로 값을 저장하고 비교하는 비용이 있다.

따라서 간단한 계산에는 오히려 useMemo가 더 비효율적일 수 있다.

주의

useMemo는 “모든 계산에 쓰는 Hook”이 아니다.

정말 계산 비용이 크거나, 렌더링마다 다시 계산되는 것이 문제일 때 사용한다.

8. 언제 useMemo를 사용하는가?

  • 무거운 filter, map, sort 계산
  • 큰 배열 검색
  • 비용이 큰 수학 계산
  • 렌더링마다 다시 계산되는 것을 막고 싶을 때
  • 의존성 값이 바뀔 때만 다시 계산하고 싶을 때

9. useMemo 핵심 정리

  • useMemo는 계산 결과를 기억하는 Hook이다.
  • 컴포넌트를 기억하는 것이 아니라 값 자체를 기억한다.
  • 의존성 배열 값이 바뀌면 다시 계산한다.
  • 무거운 계산 최적화에 사용한다.
  • fetch 같은 외부 작업은 useMemo가 아니라 useEffect에서 처리한다.
  • 모든 계산에 useMemo를 사용할 필요는 없다.

Chapter 12
useCallback

1. 왜 사용하는가?

컴포넌트가 다시 렌더링되면 내부에서 만든 함수도 새로 만들어진다. useCallback은 함수를 재사용하고 싶을 때 사용한다.

렌더링 ↓ 함수 새로 생성 ↓ 자식 컴포넌트에 함수 props 전달 ↓ 자식이 불필요하게 다시 렌더링될 수 있음

2. 예제

import { useCallback, useState, memo } from "react";

const ChildButton = memo(function ChildButton({ onClick }) {
    console.log("ChildButton 렌더링");

    return <button onClick={onClick}>증가</button>;
});

function Counter() {
    const [count, setCount] = useState(0);

    const increase = useCallback(() => {
        setCount((prev) => prev + 1);
    }, []);

    return (
        <div>
            <h1>{count}</h1>
            <ChildButton onClick={increase} />
        </div>
    );
}

3. useMemo와 useCallback 차이

Hook 기억하는 것
useMemo 계산 결과 값
useCallback 함수 자체
useCallback 핵심
  • 함수를 캐싱한다.
  • 주로 memo된 자식 컴포넌트에 함수를 props로 넘길 때 사용한다.
  • 모든 함수에 무조건 사용할 필요는 없다.
  • 성능 최적화가 필요한 상황에서 사용한다.

Chapter 13
useContext

1. 왜 사용하는가?

props는 부모에서 자식으로 값을 전달한다. 그런데 여러 단계 아래 컴포넌트까지 계속 props를 넘기면 코드가 불편해진다.

App ↓ user props Layout ↓ user props Header ↓ user props Profile

이런 props drilling을 줄이기 위해 context를 사용한다.

import { createContext, useContext, useState } from "react";

const ThemeContext = createContext(null);

function App() {
    const [dark, setDark] = useState(false);

    return (
        <ThemeContext.Provider value={{ dark, setDark }}>
            <Header />
            <Content />
        </ThemeContext.Provider>
    );
}

function Header() {
    const { dark, setDark } = useContext(ThemeContext);

    return (
        <button onClick={() => setDark(!dark)}>
            {dark ? "다크모드" : "라이트모드"}
        </button>
    );
}

function Content() {
    const { dark } = useContext(ThemeContext);

    return (
        <main style={{ background: dark ? "#222" : "#fff" }}>
            화면 내용
        </main>
    );
}

2. 언제 사용하는가?

  • 로그인 사용자 정보
  • 다크모드 / 라이트모드
  • 언어 설정
  • 공통 설정값
주의

Context는 값 전달을 쉽게 해주는 도구이다. 모든 state를 Context에 넣는 것이 항상 좋은 것은 아니다. 값이 자주 바뀌거나 상태 변경 로직이 복잡하면 Redux, Zustand, useReducer 같은 다른 방법이 더 적합할 수 있다.

Chapter 14
useReducer

1. 왜 사용하는가?

state 변경 로직이 단순하면 useState로 충분하다.

단순한 state: count 증가 input 값 변경 modal 열기/닫기

하지만 상태 변경 경우가 많아지면 이벤트 함수 안이 복잡해진다. 이때 useReducer를 사용하면 상태 변경 규칙을 한곳에 모을 수 있다.

dispatch(action) ↓ reducer가 action.type 확인 ↓ 다음 state 반환 ↓ React가 리렌더링

2. 예제

import { useReducer } from "react";

const initialState = {
    count: 0
};

function reducer(state, action) {
    switch (action.type) {
        case "increase":
            return {
                count: state.count + 1
            };

        case "decrease":
            return {
                count: state.count - 1
            };

        case "reset":
            return {
                count: 0
            };

        default:
            return state;
    }
}

function Counter() {
    const [state, dispatch] = useReducer(reducer, initialState);

    return (
        <div>
            <h1>{state.count}</h1>

            <button onClick={() => dispatch({ type: "increase" })}>
                증가
            </button>

            <button onClick={() => dispatch({ type: "decrease" })}>
                감소
            </button>

            <button onClick={() => dispatch({ type: "reset" })}>
                초기화
            </button>
        </div>
    );
}
useReducer 핵심
  • useState와 비슷하지만 상태 변경 로직을 reducer 함수로 분리한다.
  • dispatch로 어떤 행동이 발생했는지 전달한다.
  • 복잡한 form, todo, 상태 전환이 많은 화면에 적합하다.
  • Redux를 이해하기 전 단계로도 좋다.

Chapter 15
Custom Hook

1. 왜 사용하는가?

여러 컴포넌트에서 같은 Hook 로직이 반복되면 Custom Hook으로 분리한다.

반복되는 로직: input 상태 관리 fetch 요청 toggle 상태 localStorage 저장 타이머

2. useInput 예제

import { useState } from "react";

function useInput(initialValue = "") {
    const [value, setValue] = useState(initialValue);

    function onChange(e) {
        setValue(e.target.value);
    }

    return {
        value,
        onChange
    };
}

function LoginForm() {
    const username = useInput("");
    const password = useInput("");

    return (
        <div>
            <input placeholder="아이디" {...username} />
            <input placeholder="비밀번호" {...password} />

            <p>아이디: {username.value}</p>
        </div>
    );
}

3. Custom Hook 규칙

  • 이름은 반드시 use로 시작한다.
  • 내부에서 다른 Hook을 사용할 수 있다.
  • 컴포넌트가 아니라 로직을 재사용하기 위한 함수이다.
Custom Hook 핵심

화면 JSX를 재사용하는 것은 컴포넌트, 상태와 로직을 재사용하는 것은 Custom Hook이다.

URL에 따라 다른 화면을 보여주기 위해, 새로고침해도 현재 URL에 맞는 화면을 보여주기 위해, 뒤로가기와 앞으로가기를 사용하기 위해, 공유 가능한 주소를 만들기 위해 사용한다.

문제 2 정답

a 태그는 일반 문서 이동을 수행하고 새로고침이 발생할 수 있다. Link는 React Router가 URL을 바꾸고 컴포넌트를 교체하여 SPA 방식으로 이동한다.

문제 6 정답

문제 8 정답

문제 9 정답

상태 변경 경우가 많고 로직이 복잡할 때, reducer 함수에 상태 변경 규칙을 모아서 관리하기 위해 사용한다.

문제 10 정답

여러 컴포넌트에서 반복되는 Hook 로직을 함수로 분리해서 재사용하기 위해 사용한다.

수업 마무리

  • React Router는 URL과 컴포넌트를 연결한다.
  • Routes와 Route로 경로별 화면을 설정한다.
  • Link는 새로고침 없이 URL을 이동한다.
  • useParams는 URL 경로의 동적 값을 읽는다.
  • useNavigate는 코드에서 페이지를 이동할 때 사용한다.
  • useSearchParams는 검색어, 필터, 페이지 번호 같은 query string을 다룬다.
  • Outlet은 중첩 라우팅에서 자식 화면이 들어갈 위치이다.
  • useEffect는 렌더링 이후 외부 시스템과 동기화할 때 사용한다.
  • useRef는 렌더링과 상관없는 값이나 DOM 참조를 저장한다.
  • useMemo는 계산 결과를 기억한다.
  • useCallback은 함수를 기억한다.
  • useContext는 여러 컴포넌트가 공통 값을 쉽게 사용하게 한다.
  • useReducer는 복잡한 상태 변경 로직을 reducer로 분리한다.
  • Custom Hook은 반복되는 Hook 로직을 재사용하기 위해 만든다.
