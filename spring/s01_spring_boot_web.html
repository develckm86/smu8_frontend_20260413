Spring Boot Web MVC 입문 교안

이 교안은 Spring Boot Web을 처음 배우는 학습자를 대상으로 합니다. Spring Boot가 왜 필요한지부터 Embedded Tomcat, Thymeleaf 화면 처리, Controller 요청·응답 처리, RestController 기반 JSON API 응답까지 한 흐름으로 다룹니다.

수업 대상 Java 기본 문법 학습자
권장 시간 3시간 30분 ~ 4시간
실습 환경 Java 17+, Maven, Spring Boot
핵심 결과물 HTML 화면 + JSON API

1. 수업 개요

이번 수업의 핵심은 “Spring Boot Web 요청이 들어오면 어떤 흐름으로 Controller까지 전달되고, 최종적으로 HTML 또는 JSON 응답이 만들어지는가”를 이해하는 것입니다.

수업 목표

  • Spring Boot가 무엇이고 왜 등장했는지 설명할 수 있다.
  • Spring Boot Web + Thymeleaf 프로젝트를 생성하고 실행할 수 있다.
  • 내장 Tomcat, DispatcherServlet, Controller, View Resolver, Thymeleaf의 관계를 설명할 수 있다.
  • @Controller를 사용해 HTML 화면을 응답할 수 있다.
  • @RequestParam, @PathVariable, @ModelAttribute, @RequestBody로 요청 데이터를 받을 수 있다.
  • @RestController로 문자열, 객체, 리스트, 상태 코드, JSON 응답을 만들 수 있다.
  • @Controller와 @RestController의 차이를 설명할 수 있다.

2. Spring Boot란?

2-1. Spring Framework만 사용할 때의 불편함

Spring Framework는 강력하지만, 예전 방식으로 웹 애플리케이션을 만들면 설정해야 할 것이 많았습니다. 간단한 웹 페이지 하나를 띄우기 위해서도 의존성, DispatcherServlet, ViewResolver, 외부 Tomcat, 배포 방식 등을 직접 맞춰야 했습니다.

강의 질문 “웹 페이지 하나 띄우려고 설정 파일을 몇 개나 만들어야 할까?”라고 질문하면서 Spring Boot의 필요성을 자연스럽게 끌어냅니다. 
Spring Framework만 사용했을 때 필요한 작업 예시

1. 의존성 직접 선택
2. Spring MVC 설정
3. DispatcherServlet 설정
4. ViewResolver 설정
5. Tomcat 같은 WAS 설치
6. web.xml 또는 Java Config 설정
7. 배포용 WAR 생성
8. 외부 Tomcat에 배포

2-2. Spring Boot의 한 줄 정의

핵심 정의 Spring Boot는 Spring 기반 애플리케이션을 쉽고 빠르게 만들고, 바로 실행하고, 운영 환경에 배포하기 좋게 도와주는 도구입니다.

강의에서는 다음처럼 단순하게 설명하면 좋습니다. 

Spring Boot = Spring을 더 쉽게 쓰기 위한 실행·설정·배포 도구

2-3. 언제, 무슨 목적으로 나왔는가?

Spring Boot는 2014년에 정식으로 등장했습니다. 등장 목적은 분명합니다. Spring 애플리케이션을 만들 때 반복적으로 작성하던 설정을 줄이고, 내장 서버를 이용해 애플리케이션을 바로 실행할 수 있게 하며, 클라우드와 마이크로서비스 환경에 더 쉽게 배포할 수 있게 하는 것입니다.

강의용 요약 Spring Boot는 “설정 지옥을 줄이고, 내장 서버로 바로 실행하며, 클라우드와 마이크로서비스 환경에 쉽게 배포하기 위해” 등장했습니다.

2-4. Spring Boot의 핵심 특징

자동 설정

프로젝트에 추가된 라이브러리를 보고 필요한 설정을 자동으로 적용합니다.

Starter 의존성

웹, Thymeleaf, JPA 같은 기능에 필요한 라이브러리를 묶음으로 제공합니다.

내장 서버

별도의 Tomcat 설치 없이 main() 실행만으로 웹 서버가 시작됩니다.

5. Spring Boot Web 동작 원리

5-1. 전체 요청 흐름

1. 브라우저가 HTTP 요청을 보낸다.
↓
2. 내장 Tomcat이 요청을 받는다.
↓
3. DispatcherServlet이 Spring MVC 요청 처리를 시작한다.
↓
4. HandlerMapping이 실행할 Controller 메서드를 찾는다.
↓
5. Controller가 요청을 처리하고 Model 또는 응답 데이터를 만든다.
↓
6. 화면 응답이면 Thymeleaf가 HTML을 만든다.
↓
7. JSON 응답이면 객체가 JSON으로 변환된다.
↓
8. 브라우저 또는 클라이언트가 응답을 받는다.

5-2. 핵심 구성 요소

구성 요소 역할
Embedded Tomcat HTTP 요청을 받는 내장 웹 서버입니다.
DispatcherServlet Spring MVC의 중앙 입구 역할을 합니다.
HandlerMapping 요청 URL과 HTTP 메서드에 맞는 Controller 메서드를 찾습니다.
Controller 요청을 처리하고 화면 이름 또는 응답 데이터를 반환합니다.
Model 화면에 전달할 데이터를 담습니다.
ViewResolver Controller가 반환한 view 이름을 실제 HTML 템플릿과 연결합니다.
Thymeleaf Model 데이터를 HTML에 넣어 최종 HTML을 만듭니다.
HttpMessageConverter Java 객체를 JSON 같은 HTTP 응답 body로 변환합니다.
핵심 구분 @Controller는 보통 HTML 화면을 반환하고, @RestController는 보통 JSON 데이터를 반환합니다.

6. Thymeleaf 화면 만들기

Thymeleaf는 서버에서 HTML을 완성해 브라우저에 보내는 템플릿 엔진입니다. Controller가 Model에 데이터를 담으면, Thymeleaf는 그 데이터를 HTML에 출력합니다.

6-1. 첫 번째 Controller

package com.example.webclass.controller;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class HomeController {

    @GetMapping("/")
    public String index(Model model) {
        model.addAttribute("title", "Spring Boot Web 수업");
        model.addAttribute("message", "Thymeleaf 화면입니다.");
        return "index";
    }
}

6-2. templates/index.html

<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title th:text="${title}">기본 제목</title>
</head>
<body>
    <h1 th:text="${title}">제목</h1>
    <p th:text="${message}">메시지</p>

    <a href="/hello?name=홍길동">hello 페이지로 이동</a>
</body>
</html>

6-3. return "index"의 의미

중요 @Controller에서 return "index";는 문자열 index를 브라우저에 보내는 것이 아닙니다. templates/index.html 파일을 찾아서 렌더링하라는 뜻입니다.

7. Controller와 요청 처리

7-1. Controller의 기본 목적

@Controller는 웹 요청을 받아 처리하고, 주로 HTML 화면을 반환할 때 사용합니다. 

@Controller
public class PageController {
}

7-2. GET 요청 처리

@GetMapping("/hello")
public String hello() {
    return "hello";
}

@GetMapping("/hello")는 브라우저가 GET /hello 요청을 보냈을 때 이 메서드를 실행하라는 뜻입니다.

7-3. Query String 처리: @RequestParam

요청 예시는 다음과 같습니다.

GET /hello?name=홍길동

Controller에서는 @RequestParam으로 query string 값을 받을 수 있습니다.

@GetMapping("/hello")
public String hello(@RequestParam String name, Model model) {
    model.addAttribute("name", name);
    return "hello";
}

templates/hello.html

<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8">
    <title>Hello</title>
</head>
<body>
    <h1>Hello</h1>
    <p>
        안녕하세요,
        <strong th:text="${name}">이름</strong>
        님!
    </p>
</body>
</html>

7-4. URL 경로 변수 처리: @PathVariable

요청 예시는 다음과 같습니다.

GET /members/10
@GetMapping("/members/{id}")
public String memberDetail(@PathVariable Long id, Model model) {
    model.addAttribute("id", id);
    return "member-detail";
}
구분 @RequestParam은 /search?keyword=spring처럼 물음표 뒤의 값을 받을 때 사용하고, @PathVariable은 /members/10처럼 URL 경로 안의 값을 받을 때 사용합니다.

8. 폼 요청 처리

8-1. DTO 만들기

폼에서 넘어온 여러 값을 하나의 객체로 받기 위해 DTO 클래스를 만듭니다. 

package com.example.webclass.dto;

public class MemberForm {

    private String name;
    private int age;

    public MemberForm() {
    }

    public MemberForm(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    public void setName(String name) {
        this.name = name;
    }

    public void setAge(int age) {
        this.age = age;
    }
}

@PostMapping("/members")
public String saveMember(@ModelAttribute MemberForm form, Model model) {

}

9-7. Servlet API 직접 사용

@GetMapping("/raw")
public String raw(HttpServletRequest request, HttpServletResponse response, Model model) {
    String name = request.getParameter("name");
    model.addAttribute("name", name);
    return "raw-result";
}
강의 포인트 Servlet API를 직접 사용할 수는 있지만, 실무에서는 가능한 한 @RequestParam, @PathVariable, @ModelAttribute, @RequestBody 같은 Spring MVC 방식의 파라미터 바인딩을 우선 사용합니다.

9-8. ModelAndView 반환

@GetMapping("/model-and-view")
public ModelAndView modelAndView() {
    ModelAndView mav = new ModelAndView("mav-page");
    mav.addObject("message", "ModelAndView 예제입니다.");
    return mav;
}

9-9. redirect

@PostMapping("/login")
public String login(@RequestParam String username) {
    return "redirect:/";
}

redirect:/는 브라우저에게 “이 주소로 다시 요청하라”고 알려주는 응답입니다.

9-10. forward

@GetMapping("/old")
public String oldPage() {
    return "forward:/new";
}

forward:/new는 서버 내부에서 다른 경로로 요청을 전달합니다. 브라우저 주소는 바뀌지 않습니다.

10. @Controller와 @ResponseBody

10-1. 문자열 자체를 응답하고 싶을 때

@Controller에서 문자열을 반환하면 기본적으로 view 이름으로 해석됩니다. 문자열 자체를 HTTP 응답 body로 보내고 싶다면 @ResponseBody를 붙입니다. 

@Controller
public class TextController {

11. RestController의 목적과 응답 방법

11-1. RestController란?

@RestController는 @Controller와 @ResponseBody를 합친 개념입니다. 클래스 안의 메서드 반환값은 기본적으로 view 이름이 아니라 HTTP 응답 body로 처리됩니다.

한 줄 정리 @Controller는 화면을 만들고, @RestController는 데이터를 보냅니다.

11-2. 기본 RestController

11-9. ResponseEntity로 상태 코드 제어

@GetMapping("/api/status")
public ResponseEntity<String> status() {

            .status(201)
            .body("created");

상황 예시 코드 의미

11-10. @Controller와 @RestController 비교

구분 @Controller @RestController
주 목적 HTML 화면 반환 데이터 반환
문자열 반환 view 이름으로 해석 문자열 자체를 body로 응답
주 사용처 웹 페이지, 관리자 화면, 폼 화면 REST API, JSON API
JSON 반환 @ResponseBody 필요 기본 적용
예시 return "index"; → index.html return "hello"; → hello 문자열 응답

13. 강의 중 꼭 강조할 오해 포인트

오해 1. return "index"는 문자열 응답이다?

아닙니다. @Controller에서는 보통 templates/index.html을 찾으라는 view 이름입니다.

오해 2. @RestController에서도 HTML 파일이 자동으로 반환된다?

아닙니다. @RestController에서 return "index";를 하면 브라우저에는 index라는 문자열이 그대로 응답됩니다.

오해 3. @RequestParam과 @PathVariable은 같다?

다릅니다. @RequestParam은 query string, @PathVariable은 URL 경로 값을 받습니다.

오해 4. @ModelAttribute와 @RequestBody는 같다?

다릅니다. @ModelAttribute는 HTML form 요청에 자주 쓰고, @RequestBody는 JSON body 요청에 자주 씁니다.

최종 정리

Spring Boot는 Spring을 쉽게 실행하고 배포하기 위한 도구입니다. Spring Boot Web은 내장 Tomcat을 사용해서 별도의 WAS 설치 없이 웹 애플리케이션을 실행할 수 있습니다.

@Controller는 HTML 화면을 반환할 때 주로 사용하고, Thymeleaf는 서버에서 HTML을 동적으로 만들어 줍니다. @RestController는 JSON API를 만들 때 주로 사용하며, 객체를 반환하면 Spring이 자동으로 JSON으로 변환해 줍니다. 

요청 데이터 처리 방식

@RequestParam   → query string
@PathVariable   → URL 경로 값
@ModelAttribute → HTML form 데이터
@RequestBody    → JSON body
ResponseEntity  → 상태 코드, 헤더, body 제어

핵심 흐름은 다음 한 줄로 정리할 수 있습니다. 

요청 → Tomcat → DispatcherServlet → Controller → View 또는 JSON 응답
