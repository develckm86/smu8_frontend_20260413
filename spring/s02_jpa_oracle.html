1. 수업 목표

이번 수업에서는 Spring Boot Web과 JPA를 이용해서 Oracle DB의 DEPT, EMP 테이블을 다루는 웹 애플리케이션을 만든다.

수업이 끝나면 할 수 있는 것
  • Spring Boot 프로젝트에서 Oracle DB를 연결할 수 있다.
  • DEPT, EMP 테이블을 JPA Entity로 매핑할 수 있다.
  • Controller, Service, Repository, Entity, DTO의 역할을 구분할 수 있다.
  • 영속성 컨텍스트와 변경 감지를 설명할 수 있다.
  • 부서 등록, 목록 조회, 수정, 삭제 화면을 만들 수 있다.
  • 부서 삭제 시 해당 부서 사원의 DEPTNO를 NULL로 바꾸고 부서를 삭제할 수 있다.
  • @Transactional의 commit, rollback 기준을 설명할 수 있다.
  • Checked Exception과 Unchecked Exception의 rollback 차이를 설명할 수 있다.

이번 수업에서는 RestController는 다루지 않는다. 모든 응답은 @Controller와 Thymeleaf 화면으로 처리한다.

3. 전체 요청 흐름 먼저 보기

코드 작성 전에 Spring Boot Web + JPA의 큰 흐름을 먼저 잡는다.

브라우저→ Controller→ Service→ Repository→ JPA→ Oracle DB

예: 부서 목록 조회

  1. 사용자가 /depts 주소로 접속한다.
  2. Controller가 요청을 받는다.
  3. Controller가 Service에게 부서 목록을 요청한다.
  4. Service가 Repository를 통해 DB 조회를 요청한다.
  5. Repository가 JPA를 이용해 Oracle DB에서 DEPT 데이터를 조회한다.
  6. 조회된 데이터를 화면에 보여주기 좋은 DTO로 바꾼다.
  7. Controller가 Model에 데이터를 담는다.
  8. Thymeleaf가 HTML 화면을 만든다.
  9. 브라우저에 부서 목록 화면이 출력된다.

5. JPA를 사용하는 이유

JPA를 사용하기 전에는 SQL을 직접 작성하고, DB 연결과 결과 변환을 직접 처리해야 했다.

SQL 방식

INSERT INTO DEPT(DEPTNO, DNAME, LOC)
VALUES (50, 'DEVELOP', 'SEOUL');

UPDATE DEPT
SET DNAME = 'DEV TEAM',
    LOC = 'BUSAN'
WHERE DEPTNO = 50;

DELETE FROM DEPT
WHERE DEPTNO = 50;

JDBC를 직접 쓰면 반복되는 일

  1. DB 연결 얻기
  2. SQL 작성
  3. PreparedStatement 생성
  4. 파라미터 바인딩
  5. SQL 실행
  6. ResultSet 처리
  7. ResultSet을 Java 객체로 변환
  8. 자원 반납
  9. commit, rollback 처리

JPA 방식

Dept dept = Dept.builder()
        .deptno(50)
        .dname("DEVELOP")
        .loc("SEOUL")
        .build();

deptRepository.save(dept);
JPA 한 줄 정리

JPA는 DB 테이블을 Java 객체처럼 다룰 수 있게 도와주는 기술이다.

단, JPA는 SQL을 몰라도 되는 기술이 아니다. 테이블, 컬럼, 기본키, 외래키, 조인, 트랜잭션을 이해해야 잘 사용할 수 있다.

7. Entity

Entity는 DB 테이블과 연결되는 Java 클래스다. DEPT 테이블은 Java에서 Dept 클래스로 표현한다.

@Entity
@Table(name = "DEPT")
public class Dept {
    @Id
    @Column(name = "DEPTNO")
    private Integer deptno;

    @Column(name = "DNAME")
    private String dname;

    @Column(name = "LOC")
    private String loc;
}
JavaDB
Dept 클래스DEPT 테이블
deptno 필드DEPTNO 컬럼
dname 필드DNAME 컬럼
loc 필드LOC 컬럼
Entity의 특징
  • DB 테이블과 연결된다.
  • 기본키를 가진다.
  • JPA가 영속성 컨텍스트에서 관리한다.
  • 값이 변경되면 UPDATE SQL로 이어질 수 있다.
  • 그래서 아무 곳에서나 함부로 변경하지 않도록 주의해야 한다.

8. 영속성 컨텍스트

영속성 컨텍스트는 JPA가 Entity를 관리하는 공간이다.

학생용 정의

영속성 컨텍스트는 JPA의 작업 공간이다. JPA는 DB에서 가져온 Entity를 바로 버리지 않고, 영속성 컨텍스트에 보관하면서 변경 여부를 추적한다.

Dept dept = deptRepository.findById(10).orElseThrow();

위 코드가 실행되면 내부적으로 다음 일이 일어난다.

  1. Oracle DB에서 DEPTNO = 10인 부서를 조회한다.
  2. 조회 결과로 Dept 객체를 만든다.
  3. Dept 객체를 영속성 컨텍스트에 저장한다.
  4. Java 코드에 Dept 객체를 반환한다.

Entity 상태

상태의미예시
비영속 상태JPA가 아직 관리하지 않는 상태new로 만든 객체
영속 상태JPA가 관리하는 상태save() 또는 findById()로 관리되는 객체

1차 캐시

영속성 컨텍스트는 1차 캐시 역할도 한다. 같은 트랜잭션 안에서 같은 Entity를 다시 조회하면 DB로 바로 가지 않고 영속성 컨텍스트에서 먼저 찾는다.

@Transactional
public void cacheTest() {
    Dept dept1 = deptRepository.findById(10).orElseThrow();
    Dept dept2 = deptRepository.findById(10).orElseThrow();

    System.out.println(dept1 == dept2); // true가 될 수 있음
}

9. 변경 감지와 flush

변경 감지

JPA에서 수정은 다음 흐름으로 이해하면 쉽다.

조회→ 영속 상태→ 값 변경→ 트랜잭션 종료→ UPDATE 
@Transactional
public void update(Integer deptno, DeptUpdateForm form) {
    Dept dept = findDept(deptno);
    dept.changeInfo(form.getDname(), form.getLoc());
}

위 코드에는 deptRepository.save(dept)가 없다. 그런데도 UPDATE가 실행된다.

  1. findDept(deptno)로 Dept를 조회한다.
  2. 조회된 Dept는 영속 상태가 된다.
  3. JPA는 조회 당시 값을 기억한다.
  4. changeInfo()로 값이 변경된다.
  5. 트랜잭션이 끝날 때 JPA가 원래 값과 현재 값을 비교한다.
  6. 바뀐 값이 있으면 UPDATE SQL을 실행한다.
변경 감지 한 줄 정리

변경 감지는 영속 상태 Entity의 값 변경을 JPA가 감지해서 UPDATE SQL을 실행하는 기능이다.

flush

flush는 영속성 컨텍스트의 변경 내용을 SQL로 DB에 보내는 과정이다.

구분의미
flushINSERT, UPDATE, DELETE SQL을 DB에 보낸다.
commit트랜잭션을 최종 확정한다.
rollback트랜잭션 안에서 실행된 작업을 취소한다.
주의

flush는 commit이 아니다. flush 이후에 오류가 발생해서 rollback되면 flush로 보낸 SQL도 취소된다.

10. 계층 구조

Spring Boot Web + JPA 프로젝트는 역할을 나누어 작성한다.

Controller→ Service→ Repository→ Entity+ DTO
계층역할
Controller웹 요청을 받고 화면을 반환한다.
Service업무 규칙과 트랜잭션을 처리한다.
RepositoryDB 접근을 담당한다.
EntityDB 테이블과 연결되는 객체다.
DTO화면과 계층 사이에서 데이터를 전달한다.

11. Controller

Controller는 사용자의 요청을 받는 계층이다.

@GetMapping("/depts")
public String deptList(Model model) {
    List<DeptResponse> depts = deptService.findAll();
    model.addAttribute("depts", depts);
    return "dept-list";
}

Controller의 역할

  • 어떤 URL 요청이 들어왔는지 받는다.
  • 요청 파라미터나 폼 데이터를 받는다.
  • Service를 호출한다.
  • 결과를 Model에 담는다.
  • 보여줄 HTML 화면 이름을 반환한다.
Controller는 DB를 직접 다루지 않는다

Controller는 웹 요청과 화면 응답에 집중한다. DB 저장, 삭제 순서, 트랜잭션 처리는 Service가 담당한다.

12. Service

Service는 애플리케이션의 업무 규칙과 트랜잭션을 처리하는 계층이다.

업무 규칙이란?

데이터를 처리할 때 반드시 지켜야 하는 규칙과 순서다.

이번 예제의 업무 규칙

  • 이미 존재하는 부서번호는 등록할 수 없다.
  • 부서번호는 기본키이므로 수정하지 않는다.
  • 부서명과 지역만 수정한다.
  • 부서를 삭제할 때 해당 부서의 사원들이 있으면 먼저 사원의 부서번호를 NULL로 바꾼다.
  • 사원의 부서번호를 NULL로 바꾼 뒤 부서를 삭제한다.
  • 이 과정 중 하나라도 실패하면 전체 작업을 취소한다.

Service를 분리하는 이유

  • Controller를 단순하게 유지할 수 있다.
  • 업무 규칙을 한 곳에 모을 수 있다.
  • 여러 DB 작업을 하나의 트랜잭션으로 묶을 수 있다.
  • 같은 기능을 여러 화면에서 재사용할 수 있다.
  • 테스트하기 쉬워진다.
핵심 정리

Controller는 요청을 받고, Service는 처리 순서와 규칙을 결정한다.

13. Repository

Repository는 DB 접근을 담당하는 계층이다. JPA에서는 JpaRepository를 상속하면 기본 CRUD 기능을 사용할 수 있다.

public interface DeptRepository extends JpaRepository<Dept, Integer> {
}
표현의미
Dept이 Repository가 관리할 Entity
IntegerDept Entity의 기본키 타입

이제 다음 메서드를 바로 사용할 수 있다.

save()findById()findAll()delete()existsById()count()flush()

Repository의 한계

Repository는 DB 접근을 담당한다. “부서를 삭제하기 전에 사원의 DEPTNO를 NULL로 바꾼다” 같은 업무 규칙은 Repository가 아니라 Service에 둔다.

14. Entity와 DTO를 구분하는 이유

Entity

DB와 연결되는 객체다. JPA가 관리하고, 변경 감지의 대상이 된다.

DTO

데이터를 전달하는 객체다. 화면 요청값이나 응답값을 담는다.

Entity의 특징

  • DB 테이블과 매핑된다.
  • JPA가 영속성 컨텍스트에서 관리한다.
  • 변경 감지의 대상이다.
  • 값이 바뀌면 DB UPDATE로 이어질 수 있다.
  • DB 구조와 밀접하게 연결된다.

DTO의 특징

  • 화면이나 계층 사이에서 데이터를 전달한다.
  • JPA가 관리하지 않는다.
  • DB 테이블과 직접 연결되지 않는다.
  • 화면에 필요한 데이터만 담을 수 있다.

왜 Entity를 화면에서 직접 받으면 안 좋은가?

@PostMapping("/depts")
public String createDept(@ModelAttribute Dept dept) {
    deptRepository.save(dept);
    return "redirect:/depts";
}

위처럼 Entity를 직접 받을 수도 있지만 좋은 방식은 아니다.

  • 화면 입력값이 Entity에 직접 들어간다.
  • Entity는 DB와 연결되는 중요한 객체인데 외부 요청과 바로 연결된다.
  • 화면 구조가 바뀌면 Entity도 영향을 받을 수 있다.
  • Entity에 화면에서 받으면 안 되는 필드가 있을 수도 있다.
  • 검증, 변환, 화면 전용 데이터 처리가 어려워진다.
구분EntityDTO
목적DB 테이블과 매핑데이터 전달
JPA 관리관리됨관리되지 않음
영속성 컨텍스트들어감들어가지 않음
변경 감지적용됨적용 안 됨
사용 위치Service, Repository 내부Controller 요청/응답, 화면 출력
DB 구조 의존성높음낮음
핵심 정리

Entity는 보호해야 하는 DB 연결 객체다. DTO는 화면과 계층 사이에서 데이터를 옮기는 객체다.

15. Lombok

Lombok은 Java의 반복 코드를 줄여주는 도구다.

Java 클래스에는 보통 getter, setter, 기본 생성자, 생성자, toString 같은 코드가 반복된다. Lombok을 쓰면 애노테이션으로 줄일 수 있다.

@Getter
@Setter
@NoArgsConstructor
public class DeptCreateForm {
    private Integer deptno;
    private String dname;
    private String loc;
}
애노테이션의미
@Gettergetter 생성
@Settersetter 생성
@NoArgsConstructor기본 생성자 생성
@AllArgsConstructor모든 필드를 받는 생성자 생성
@RequiredArgsConstructorfinal 필드를 받는 생성자 생성
@Builder빌더 패턴 생성
@Datagetter, setter, toString, equals, hashCode 등을 한 번에 생성
Entity에서는 @Data를 권장하지 않음

모든 setter가 열리고, equals/hashCode/toString 자동 생성이 JPA Entity와 맞지 않을 수 있다. Entity에서는 보통 @Getter, @NoArgsConstructor(access = AccessLevel.PROTECTED) 조합을 사용한다.

20. Service 코드

DeptService.java

package com.example.deptjpa.service;

import com.example.deptjpa.dto.DeptCreateForm;
import com.example.deptjpa.dto.DeptResponse;
import com.example.deptjpa.dto.DeptUpdateForm;
import com.example.deptjpa.entity.Dept;
import com.example.deptjpa.entity.Emp;
import com.example.deptjpa.repository.DeptRepository;
import com.example.deptjpa.repository.EmpRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)
public class DeptService {

    private final DeptRepository deptRepository;
    private final EmpRepository empRepository;

    public List<DeptResponse> findAll() {
        return deptRepository.findAll(Sort.by(Sort.Direction.ASC, "deptno"))
                .stream()
                .map(dept -> new DeptResponse(
                        dept,
                        empRepository.countByDept_Deptno(dept.getDeptno())
                ))
                .toList();
    }

    public DeptResponse findOne(Integer deptno) {
        Dept dept = findDept(deptno);
        long empCount = empRepository.countByDept_Deptno(deptno);
        return new DeptResponse(dept, empCount);
    }

    @Transactional
    public void create(DeptCreateForm form) {
        if (deptRepository.existsById(form.getDeptno())) {
            throw new IllegalArgumentException("이미 존재하는 부서번호입니다. deptno=" + form.getDeptno());
        }

        Dept dept = form.toEntity();
        deptRepository.save(dept);
    }

    @Transactional
    public void update(Integer deptno, DeptUpdateForm form) {
        Dept dept = findDept(deptno);
        dept.changeInfo(form.getDname(), form.getLoc());
    }

    @Transactional
    public void deleteDeptAndDetachEmployees(Integer deptno) {
        Dept dept = findDept(deptno);

        List<Emp> employees = empRepository.findByDept_Deptno(deptno);

        for (Emp emp : employees) {
            emp.removeDept();
        }

        empRepository.flush();

        deptRepository.delete(dept);
    }

    @Transactional
    public void deleteDeptAndFailByUncheckedException(Integer deptno) {
        Dept dept = findDept(deptno);

        List<Emp> employees = empRepository.findByDept_Deptno(deptno);

        for (Emp emp : employees) {
            emp.removeDept();
        }

        empRepository.flush();

        deptRepository.delete(dept);

        throw new IllegalStateException("Unchecked Exception 발생: rollback 대상");
    }

    @Transactional
    public void deleteDeptAndFailByCheckedException(Integer deptno) throws Exception {
        Dept dept = findDept(deptno);

        List<Emp> employees = empRepository.findByDept_Deptno(deptno);

        for (Emp emp : employees) {
            emp.removeDept();
        }

        empRepository.flush();

        deptRepository.delete(dept);

        throw new Exception("Checked Exception 발생: 기본 설정에서는 rollback 대상 아님");
    }

    @Transactional(rollbackFor = Exception.class)
    public void deleteDeptAndFailByCheckedExceptionWithRollback(Integer deptno) throws Exception {
        Dept dept = findDept(deptno);

        List<Emp> employees = empRepository.findByDept_Deptno(deptno);

        for (Emp emp : employees) {
            emp.removeDept();
        }

        empRepository.flush();

        deptRepository.delete(dept);

        throw new Exception("Checked Exception 발생: rollbackFor 설정으로 rollback");
    }

    private Dept findDept(Integer deptno) {
        return deptRepository.findById(deptno)
                .orElseThrow(() -> new IllegalArgumentException("부서를 찾을 수 없습니다. deptno=" + deptno));
    }
}

21. Controller 코드

package com.example.deptjpa.controller;

import com.example.deptjpa.dto.DeptCreateForm;
import com.example.deptjpa.dto.DeptResponse;
import com.example.deptjpa.dto.DeptUpdateForm;
import com.example.deptjpa.dto.EmpResponse;
import com.example.deptjpa.service.DeptService;
import com.example.deptjpa.service.EmpService;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@Controller
@RequiredArgsConstructor
public class DeptController {

    private final DeptService deptService;
    private final EmpService empService;

    @GetMapping("/")
    public String home() {
        return "index";
    }

    @GetMapping("/depts")
    public String deptList(Model model) {
        List<DeptResponse> depts = deptService.findAll();
        model.addAttribute("depts", depts);
        return "dept-list";
    }

    @GetMapping("/depts/new")
    public String deptForm(Model model) {
        model.addAttribute("form", new DeptCreateForm());
        return "dept-form";
    }

    @PostMapping("/depts")
    public String createDept(@ModelAttribute DeptCreateForm form) {
        deptService.create(form);
        return "redirect:/depts";
    }

    @GetMapping("/depts/{deptno}/edit")
    public String editForm(@PathVariable Integer deptno, Model model) {
        DeptResponse dept = deptService.findOne(deptno);
        model.addAttribute("dept", dept);
        model.addAttribute("form", new DeptUpdateForm());
        return "dept-edit";
    }

    @PostMapping("/depts/{deptno}/edit")
    public String updateDept(
            @PathVariable Integer deptno,
            @ModelAttribute DeptUpdateForm form
    ) {
        deptService.update(deptno, form);
        return "redirect:/depts";
    }

    @PostMapping("/depts/{deptno}/delete")
    public String deleteDept(@PathVariable Integer deptno) {
        deptService.deleteDeptAndDetachEmployees(deptno);
        return "redirect:/depts";
    }

    @GetMapping("/emps")
    public String empList(Model model) {
        List<EmpResponse> emps = empService.findAll();
        model.addAttribute("emps", emps);
        return "emp-list";
    }
}

23. 트랜잭션

트랜잭션은 여러 DB 작업을 하나의 작업 단위로 묶는 것이다.

트랜잭션 한 줄 정리

모두 성공하면 commit, 중간에 실패하면 rollback한다.

부서 삭제 예제로 이해하기

부서를 삭제할 때 단순히 DEPT만 삭제하면 안 된다. EMP가 DEPT를 참조하고 있기 때문이다.

EMP.DEPTNO → DEPT.DEPTNO

따라서 순서는 다음과 같아야 한다.

  1. 해당 부서에 속한 사원들의 DEPTNO를 NULL로 변경한다.
  2. 부서를 삭제한다.
@Transactional
public void deleteDeptAndDetachEmployees(Integer deptno) {
    Dept dept = findDept(deptno);

    List<Emp> employees = empRepository.findByDept_Deptno(deptno);

    for (Emp emp : employees) {
        emp.removeDept();
    }

    empRepository.flush();

    deptRepository.delete(dept);
}

정상 흐름

트랜잭션 시작→ EMP.DEPTNO = NULL→ DEPT 삭제→ commit

실패 흐름

트랜잭션 시작→ EMP UPDATE→ DEPT DELETE 중 오류→ rollback

rollback되면 EMP UPDATE도 취소되고 DEPT DELETE도 취소된다.

24. rollback 기준

트랜잭션 rollback을 이해하려면 Java 예외를 구분해야 한다.

예외 종류예시기본 rollback
Unchecked ExceptionIllegalStateException, NullPointerExceptionrollback 함
Checked ExceptionException, IOException, SQLExceptionrollback 안 함
ErrorOutOfMemoryErrorrollback 함
핵심 문장

@Transactional은 기본적으로 RuntimeException 계열 예외가 발생하면 rollback한다.

Unchecked Exception rollback 예제

@Transactional
public void deleteDeptAndFailByUncheckedException(Integer deptno) {
    Dept dept = findDept(deptno);

    List<Emp> employees = empRepository.findByDept_Deptno(deptno);

    for (Emp emp : employees) {
        emp.removeDept();
    }

    empRepository.flush();

    deptRepository.delete(dept);

    throw new IllegalStateException("Unchecked Exception 발생");
}

IllegalStateException은 RuntimeException 계열이다. 따라서 기본 rollback 대상이다.

결과

EMP.DEPTNO = NULL 변경 취소
DEPT 삭제 취소

Checked Exception 예제

@Transactional
public void deleteDeptAndFailByCheckedException(Integer deptno) throws Exception {
    Dept dept = findDept(deptno);

    List<Emp> employees = empRepository.findByDept_Deptno(deptno);

    for (Emp emp : employees) {
        emp.removeDept();
    }

    empRepository.flush();

    deptRepository.delete(dept);

    throw new Exception("Checked Exception 발생");
}

Exception은 Checked Exception이다. 기본 설정에서는 rollback 대상이 아니다.

중요

예외가 발생했다고 해서 무조건 rollback되는 것은 아니다.

Checked Exception도 rollback하고 싶을 때

@Transactional(rollbackFor = Exception.class)
public void deleteDeptAndFailByCheckedExceptionWithRollback(Integer deptno) throws Exception {
    Dept dept = findDept(deptno);

    List<Emp> employees = empRepository.findByDept_Deptno(deptno);

    for (Emp emp : employees) {
        emp.removeDept();
    }

    empRepository.flush();

    deptRepository.delete(dept);

    throw new Exception("Checked Exception 발생");
}

rollbackFor = Exception.class를 설정하면 Checked Exception도 rollback된다.

26. 최종 정리

  • Spring Boot Web은 브라우저 요청을 받고 화면을 응답한다.
  • JPA는 Java 객체와 DB 테이블을 연결한다.
  • Entity는 DB 테이블과 매핑되는 객체다.
  • DTO는 요청과 응답 데이터를 전달하는 객체다.
  • Entity와 DTO를 분리하면 DB 구조와 화면 구조를 분리할 수 있다.
  • 영속성 컨텍스트는 JPA가 Entity를 관리하는 공간이다.
  • 영속 상태 Entity는 JPA가 변경을 추적한다.
  • 변경 감지를 이용하면 수정할 때 save를 다시 호출하지 않아도 된다.
  • Repository는 DB 접근을 담당한다.
  • Service는 업무 규칙과 트랜잭션을 담당한다.
  • Controller는 웹 요청을 받고 화면을 반환한다.
  • Lombok은 반복 코드를 줄여준다.
  • Emp는 Dept와 ManyToOne 관계를 가진다.
  • 부서를 삭제할 때는 해당 부서 사원의 DEPTNO를 NULL로 바꾼 뒤 부서를 삭제한다.
  • 이 과정은 하나의 트랜잭션으로 묶어야 한다.
  • @Transactional은 기본적으로 Unchecked Exception에서 rollback한다.
  • Checked Exception은 기본적으로 rollback하지 않는다.
  • Checked Exception도 rollback하려면 rollbackFor를 사용한다.
최종 한 문장

Spring Boot Web + JPA는 사용자의 웹 요청을 받아 Service에서 업무 규칙과 트랜잭션을 처리하고, Repository와 JPA를 통해 Oracle DB의 DEPT, EMP 데이터를 객체 중심으로 다루는 방식이다.
