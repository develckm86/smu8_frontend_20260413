2. MVC를 왜 사용하는가

웹 애플리케이션은 보통 사용자의 요청을 받고, 데이터를 처리하고, 결과 화면을 만들어 응답한다. 규모가 작을 때는 JSP 한 파일에 모든 코드를 넣어도 동작한다. 하지만 기능이 늘어나면 SQL, Java 로직, HTML 화면 코드가 뒤섞이면서 유지보수가 어려워진다. MVC는 이 문제를 해결하기 위해 역할을 분리하는 설계 방식이다.

사용자 요청→처리 로직→DB 처리→화면 출력

MVC의 세 역할

구분역할이번 수업의 예
Model 데이터와 비즈니스 로직을 담당한다. DB 조회, 등록, 수정, 삭제와 같은 작업을 처리한다. Dept, DeptDAO, DBConn
View 사용자에게 보여 줄 화면을 담당한다. 가능한 한 화면 출력만 담당한다. list.jsp, form.jsp
Controller 요청을 받아 어떤 Model을 호출하고 어떤 View로 이동할지 결정한다. DeptListController, DeptInsertController 등
교사용 설명 포인트 “MVC는 코드를 더 많이 쓰기 위한 기술이 아니라, 나중에 수정하기 쉽게 역할을 나누는 방법”이라고 설명한다. 학생들이 처음에는 파일이 많아져서 복잡하다고 느끼므로, 유지보수 관점의 장점을 반복해서 강조한다.

MVC를 사용하면 좋아지는 점

  • JSP 화면에서 SQL과 DB 연결 코드가 사라져 화면 코드가 읽기 쉬워진다.
  • DB 처리 코드를 DAO에 모아 재사용할 수 있다.
  • 요청 흐름을 Controller에서 관리하므로 URL과 기능의 관계가 명확해진다.
  • 화면 수정, SQL 수정, 요청 흐름 수정을 서로 분리해서 작업할 수 있다.

3. Model1이란 무엇인가

Model1은 JSP가 요청을 직접 받고, JSP 안에서 DB를 조회하고, JSP가 바로 HTML을 출력하는 방식이다. 즉, JSP 하나가 Controller 역할, Model 호출 역할, View 역할을 모두 담당한다.

브라우저→JSP→JDBC/DB→JSP가 HTML 출력

Model1의 특징

장점단점
  • 처음 만들기 쉽다.
  • 파일 수가 적다.
  • 간단한 테스트 페이지를 빠르게 만들 수 있다.
  • JSP에 Java 코드와 HTML이 섞인다.
  • SQL과 DB 접속 정보가 JSP에 노출된다.
  • 기능이 늘수록 JSP가 길고 복잡해진다.
  • 목록, 등록, 수정, 삭제마다 DB 연결 코드가 반복된다.
  • 화면 변경과 로직 변경이 서로 영향을 준다.
학생 질문 “JSP 하나로도 동작하는데 왜 굳이 Servlet과 DAO로 나누나요?”
답변: “동작하는 것과 유지보수하기 좋은 것은 다르다. 기능이 하나일 때는 JSP 하나가 편하지만, CRUD가 늘어나고 화면이 많아지면 같은 DB 코드가 반복되고 수정 위치가 많아져 오류가 늘어난다.”

5. Model2란 무엇인가

Model2는 Servlet이 Controller 역할을 맡고, Java 클래스가 Model 역할을 맡으며, JSP가 View 역할만 담당하는 구조이다. Servlet/JSP 수업에서는 보통 Model2를 MVC2라고도 부른다.

DBConn 싱글톤

DBConn 객체는 싱글톤으로 만든다. 하지만 Connection 객체 하나를 모든 요청이 공유하지는 않는다. 웹에서는 여러 사용자가 동시에 요청할 수 있기 때문에 하나의 Connection을 전역 공유하면 문제가 생길 수 있다.

중요 “DBConn은 싱글톤”과 “Connection을 하나만 만들어 계속 공유”는 다른 말이다. 이번 예제는 DBConn 객체만 하나로 유지하고, getConnection() 호출 때마다 새 Connection을 얻는다.
DBConn.java 
package com.example.common;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public final class DBConn {
    private static final DBConn INSTANCE = new DBConn();

    private static final String URL = "jdbc:oracle:thin:@localhost:1512/XEPDB1";
    private static final String USER = "scott";
    private static final String PASSWORD = "tiger";

    private DBConn() {
        try {
            Class.forName("oracle.jdbc.OracleDriver");
        } catch (ClassNotFoundException e) {
            throw new ExceptionInInitializerError(e);
        }
    }

    public static DBConn getInstance() {
        return INSTANCE;
    }

    public Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL, USER, PASSWORD);
    }
}

DTO는 데이터를 담는 객체이다. DEPT 테이블의 한 행을 Java 객체 하나로 표현한다.

DAO: DeptDAO

DAO는 SQL을 실행하는 클래스이다. JSP와 Controller가 SQL을 직접 알지 않아도 되도록 DB 처리 코드를 모아 둔다.

DeptDAO.java 
package com.example.dept.dao;

import com.example.common.DBConn;
import com.example.dept.model.Dept;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;

public class DeptDAO {
    private final DBConn dbConn = DBConn.getInstance();

    public List<Dept> findAll() throws SQLException {
        String sql = "SELECT deptno, dname, loc FROM dept ORDER BY deptno";
        List<Dept> deptList = new ArrayList<>();

        try (Connection conn = dbConn.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql);
             ResultSet rs = pstmt.executeQuery()) {

            while (rs.next()) {
                deptList.add(mapRow(rs));
            }
        }

        return deptList;
    }

    public Dept findByDeptno(int deptno) throws SQLException {
        String sql = "SELECT deptno, dname, loc FROM dept WHERE deptno = ?";

        try (Connection conn = dbConn.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setInt(1, deptno);

            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    return mapRow(rs);
                }
            }
        }

        return null;
    }

    public int insert(Dept dept) throws SQLException {
        String sql = "INSERT INTO dept (deptno, dname, loc) VALUES (?, ?, ?)";

        try (Connection conn = dbConn.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setInt(1, dept.getDeptno());
            pstmt.setString(2, dept.getDname());
            pstmt.setString(3, dept.getLoc());
            return pstmt.executeUpdate();
        }
    }

    public int update(Dept dept) throws SQLException {
        String sql = "UPDATE dept SET dname = ?, loc = ? WHERE deptno = ?";

        try (Connection conn = dbConn.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setString(1, dept.getDname());
            pstmt.setString(2, dept.getLoc());
            pstmt.setInt(3, dept.getDeptno());
            return pstmt.executeUpdate();
        }
    }

    public int delete(int deptno) throws SQLException {
        String sql = "DELETE FROM dept WHERE deptno = ?";

        try (Connection conn = dbConn.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setInt(1, deptno);
            return pstmt.executeUpdate();
        }
    }

    private Dept mapRow(ResultSet rs) throws SQLException {
        Dept dept = new Dept();
        dept.setDeptno(rs.getInt("deptno"));
        dept.setDname(rs.getString("dname"));
        dept.setLoc(rs.getString("loc"));
        return dept;
    }
}

11. JSTL 설명과 JSP 기본 문법 비교

JSTL은 JSP Standard Tag Library의 약자이다. JSP에서 Java Scriptlet을 줄이고, 반복문, 조건문, 출력 등을 태그 형태로 작성하게 해 주는 라이브러리이다. JSTL은 DAO나 Controller를 대신하지 않는다. JSTL은 View, 즉 JSP 화면을 더 읽기 좋게 만드는 기술이다.

JSTL을 사용하는 이유

  • JSP에서 Java 코드가 줄어든다.
  • HTML과 비슷한 태그 형태라 화면 코드가 더 읽기 쉽다.
  • c:out을 사용하면 기본적인 HTML escaping 처리를 할 수 있다.
  • 디자이너와 개발자가 JSP를 함께 볼 때 Scriptlet보다 이해하기 쉽다.

JSTL을 사용하기 위한 Maven 의존성

pom.xml에 JSTL 추가 
<!-- JSTL 수업 후 추가하는 의존성 -->
<dependency>
    <groupId>javax.servlet</groupId>
    <artifactId>jstl</artifactId>
    <version>1.2</version>
</dependency>

JSTL Core 태그 선언

<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>

자주 쓰는 JSTL 태그

태그역할JSP 기본 문법과 비교
<c:forEach>반복Java for문을 대신한다.
<c:if>단순 조건Java if문을 대신한다.
<c:choose>if/else if/elseJava if ~ else 구조를 대신한다.
<c:out>값 출력<%= %> 출력식과 escape 메서드를 대신한다.

비교 1: contextPath 출력

<!-- JSP 기본 문법 -->
<%= request.getContextPath() %>/dept/list

<!-- JSTL/EL 사용 -->
${pageContext.request.contextPath}/dept/list

비교 2: 반복 출력

%>
    <td><%= dept.getDname() %></td>
<%
    }
%>

<c:forEach var="dept" items="${deptList}">

12. 수업 진행안

단계시간수업 내용교수 포인트
도입 10분 JSP 한 파일에 모든 코드를 넣으면 어떤 문제가 생기는지 질문한다. “동작은 하지만 고치기 어렵다”를 학생이 말하게 유도한다.
Model1 설명 25분 Model1 구조와 dept_model1_list.jsp 예제를 보여 준다. DB 코드, SQL, HTML을 색으로 구분하게 한다.
Model1 문제점 토론 15분 등록, 수정, 삭제가 추가되면 어떤 중복이 생기는지 토론한다. DAO와 Controller의 필요성으로 연결한다.
Model2 설명 25분 Servlet Controller, DAO, DTO, JSP View의 역할을 설명한다. forward와 redirect의 차이를 예로 설명한다.
DB/DAO 구현 35분 Maven, OJDBC, DBConn, Dept, DeptDAO를 작성한다. DBConn 싱글톤과 Connection 공유 금지를 강조한다.
Controller 구현 45분 기능별 Controller를 작성한다. URL 하나당 역할 하나를 갖게 한다.
JSP 기본 View 구현 35분 JSTL 없이 list.jsp, form.jsp를 작성한다. Model1과 달리 JSP에 DB 코드가 없다는 점을 확인한다.
JSTL 비교 25분 JSP 기본 문법 버전과 JSTL 버전을 비교한다. JSTL은 MVC가 아니라 View 작성 도구임을 강조한다.
정리/평가 20분 확인 문제와 오류 해결 체크리스트를 확인한다. Model1 → Model2 → JSTL의 개선 흐름을 말로 설명하게 한다.

판서용 핵심 정리

판서 예시
  1. Model1: JSP가 요청 처리 + DB 처리 + 화면 출력을 모두 담당한다.
  2. Model2: Servlet이 요청 흐름을 제어하고, DAO가 DB를 처리하며, JSP는 화면만 출력한다.
  3. MVC를 쓰는 이유: 역할 분리, 중복 감소, 유지보수 향상.
  4. JSTL을 쓰는 이유: JSP 화면에서 Java Scriptlet을 줄이기 위해.
  5. DBConn은 싱글톤으로 만들 수 있지만 Connection 하나를 공유하면 안 된다.

실행 방법

# Maven 빌드
mvn clean package

# 생성 파일
# target/mvc2-dept.war

# Tomcat 배포 후 접속
http://localhost:8080/mvc2-dept/dept/list

# Model1 예제 접속
http://localhost:8080/mvc2-dept/dept_model1_list.jsp

13. 실습 과제와 확인 문제

기본 실습

  1. dept_model1_list.jsp를 실행하여 Model1 방식의 목록 출력을 확인한다.
  2. Model1 코드에서 DB 접속 코드, SQL 코드, HTML 출력 코드를 표시한다.
  3. DBConn, Dept, DeptDAO를 작성한다.
  4. /dept/list 요청으로 목록이 출력되도록 구현한다.
  5. 등록, 수정, 삭제 Controller를 순서대로 구현한다.
  6. JSP 기본 문법 버전과 JSTL 버전 코드를 비교한다.

응용 과제

  • 부서명으로 검색하는 /dept/search 기능을 추가한다.
  • 삭제 버튼 클릭 시 JavaScript confirm()으로 확인 후 삭제하게 한다.
  • 등록 시 이미 존재하는 부서번호이면 오류 메시지를 친절하게 출력한다.
  • DB 접속 정보를 Java 코드에서 분리하여 db.properties로 관리한다.

확인 문제

문제정답 방향
1. Model1과 Model2의 가장 큰 차이는 무엇인가? Model1은 JSP가 요청과 DB 처리까지 담당하고, Model2는 Servlet Controller가 요청 흐름을 담당한다.
2. MVC에서 DAO는 어떤 역할인가? DB SQL 실행과 데이터 조회, 등록, 수정, 삭제를 담당한다.
3. 조회 후에는 왜 forward를 사용하는가? Controller가 조회한 데이터를 request에 담아 JSP로 전달해야 하기 때문이다.
4. 등록, 수정, 삭제 후에는 왜 redirect를 사용하는가? 새로고침 시 같은 변경 작업이 반복 실행되는 문제를 줄이고 목록 URL로 다시 요청하게 하기 위해서이다.
5. JSTL은 MVC에서 어떤 역할을 대체하는가? Controller나 DAO를 대체하지 않는다. JSP View에서 Scriptlet을 줄이는 역할을 한다.
6. DBConn은 싱글톤인데 Connection을 공유하면 안 되는 이유는? 웹 요청은 동시에 처리될 수 있으므로 하나의 Connection을 여러 요청이 공유하면 트랜잭션, close, 동시성 문제가 생길 수 있다.

14. 오류 해결 체크리스트

증상가능한 원인해결 방법
ClassNotFoundException: oracle.jdbc.OracleDriver ojdbc 의존성이 없거나 Maven 빌드가 반영되지 않음 pom.xml에 ojdbc11 의존성을 확인하고 Maven Update/빌드
ORA-01017 계정 또는 비밀번호 오류 scott/tiger 확인, 계정 unlock 여부 확인
ORA-12514 또는 접속 실패 서비스 이름, 포트, DB 실행 상태 문제 XEPDB1, 포트 1512/1521, 리스너 상태 확인
404 Not Found URL 매핑 오류 또는 Context Path 오류 @WebServlet("/dept/list")와 접속 URL 확인
405 Method Not Allowed GET/POST 메서드 불일치 등록, 수정, 삭제는 form method가 post인지 확인
한글 깨짐 요청 인코딩 또는 JSP 인코딩 누락 request.setCharacterEncoding("UTF-8"), JSP pageEncoding 확인
JSTL 태그가 그대로 보임 JSTL 의존성 또는 taglib 선언 누락 jstl 의존성 추가, taglib 선언 확인
localhsot 접속 실패 오타 localhost로 수정
마무리 질문 학생에게 “Model1 코드와 Model2 코드 중 어느 쪽이 파일 수가 많은가?”, “그런데 왜 실무에서는 Model2 구조를 더 선호하는가?”를 질문한다. 답은 “파일 수는 늘지만 역할이 분리되어 수정과 확장이 쉬워지기 때문”이다.
