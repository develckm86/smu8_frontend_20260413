Chapter 01
React란 무엇인가

React는 사용자 인터페이스 UI를 만들기 위한 JavaScript 라이브러리이다.

React의 핵심 생각은 화면을 작은 조각인 컴포넌트로 나누고, 데이터가 바뀌면 화면을 다시 계산하는 것이다.

React의 핵심 1. 화면을 컴포넌트로 나눈다. 2. 컴포넌트는 JSX를 반환한다. 3. 데이터가 바뀌면 컴포넌트를 다시 실행한다. 4. 이전 화면과 새 화면을 비교한다. 5. 바뀐 부분만 실제 DOM에 반영한다.
수업용 한 문장

React는 “상태에 따라 화면을 다시 그려주는 UI 라이브러리”이다.

Chapter 02
컴포넌트

1. 컴포넌트란?

컴포넌트는 화면을 구성하는 독립적인 조각이다.

전체 화면 ├── Header 컴포넌트 ├── ProductList 컴포넌트 ├── ProductCard 컴포넌트 └── Footer 컴포넌트

2. 함수 컴포넌트

React에서 가장 많이 사용하는 컴포넌트 형태는 함수 컴포넌트이다.

function Header() {
    return <h1>쇼핑몰</h1>;
}

function Product() {
    return <p>상품 정보</p>;
}

function App() {
    return (
        <div>
            <Header />
            <Product />
        </div>
    );
}
중요

컴포넌트 이름은 대문자로 시작한다. 예를 들어 App, Header, ProductCard처럼 작성한다.

Chapter 03
HTML에서 React 간단히 사용하기

React는 처음 배울 때 HTML 파일 하나에서도 간단히 실행해볼 수 있다.

이 방식은 실제 프로젝트용이라기보다 React 개념을 빠르게 확인하는 실습용이다.

필요한 것 1. React 라이브러리 2. ReactDOM 라이브러리 3. Babel 4. React를 넣을 div#root
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>React CDN 실습</title>
</head>
<body>
    <h1>일반 HTML 영역</h1>

    <div id="root"></div>

    <script src="https://unpkg.com/react@18/umd/react.development.js"></script>
    <script src="https://unpkg.com/react-dom@18/umd/react-dom.development.js"></script>
    <script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

    <script type="text/babel">
        function App() {
            return <h2>React가 만든 화면</h2>;
        }

        const root = ReactDOM.createRoot(document.getElementById("root"));
        root.render(<App />);
    </script>
</body>
</html>

코드에서 꼭 볼 부분

  • <div id="root"></div>: React 화면이 들어갈 자리
  • ReactDOM.createRoot(...): React를 실행할 위치 지정
  • root.render(<App />): App 컴포넌트를 화면에 출력
  • type="text/babel": JSX가 들어있는 코드를 Babel로 변환해서 실행
주의

HTML + CDN + Babel 방식은 수업용으로 간단하지만, 실제 프로젝트에서는 Vite, Next.js 같은 개발 도구를 사용하는 것이 일반적이다.

Chapter 04
JSX와 Babel

1. JSX란?

JSX는 JavaScript 안에서 HTML처럼 화면 구조를 작성하게 해주는 문법이다.

function App() {
    const name = "홍길동";

    return (
        <div>
            <h1>{name}</h1>
            <p>React 수업입니다.</p>
        </div>
    );
}

JSX 안에서 JavaScript 값을 출력할 때는 중괄호를 사용한다.

{name} {age + 1} {isLogin ? "로그인" : "로그아웃"}

2. Babel이란?

Babel은 JSX나 최신 JavaScript 문법을 브라우저가 실행할 수 있는 JavaScript로 바꿔주는 도구이다.

JSX 코드 ↓ Babel 변환 ↓ 브라우저가 실행 가능한 JavaScript 코드
// 우리가 작성하는 JSX
const element = <h1>안녕하세요</h1>;

// Babel 변환 후 느낌
const element = React.createElement(
    "h1",
    null,
    "안녕하세요"
);
간단 정리
  • JSX는 React 화면을 HTML처럼 작성하는 문법이다.
  • 브라우저는 JSX를 그대로 이해하지 못한다.
  • Babel은 JSX를 일반 JavaScript 코드로 바꿔준다.

Chapter 05
Props

1. Props란?

Props는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 값이다.

부모 컴포넌트 ↓ props 전달 자식 컴포넌트

같은 컴포넌트를 여러 번 사용하면서 다른 값을 넣고 싶을 때 사용한다.

function Greeting(props) {
    return <h1>{props.name}님 안녕하세요</h1>;
}

function App() {
    return (
        <div>
            <Greeting name="홍길동" />
            <Greeting name="김철수" />
        </div>
    );
}

2. 구조 분해 할당으로 Props 받기

실무에서는 props.name보다 아래처럼 구조 분해 할당을 많이 사용한다.

function UserCard({ name, age, job }) {
    return (
        <div>
            <h2>{name}</h2>
            <p>나이: {age}</p>
            <p>직업: {job}</p>
        </div>
    );
}

function App() {
    return (
        <UserCard
            name="홍길동"
            age={20}
            job="학생"
        />
    );
}

3. children Props

children은 컴포넌트 태그 사이에 들어온 내용을 의미한다.

function Box({ children }) {
    return (
        <div className="box">
            {children}
        </div>
    );
}

function App() {
    return (
        <Box>
            <h2>제목</h2>
            <p>Box 안에 들어가는 내용입니다.</p>
        </Box>
    );
}

4. Props 특징

  • 부모가 자식에게 값을 전달할 때 사용한다.
  • 자식은 props를 읽어서 화면에 사용할 수 있다.
  • props는 자식 컴포넌트 안에서 직접 수정하지 않는다.
  • 다른 값을 넣으면 같은 컴포넌트도 다른 화면을 만들 수 있다.

Chapter 06
State

1. State란?

State는 컴포넌트가 기억해야 하는 값이다.

State 값이 바뀌면 React는 해당 컴포넌트를 다시 렌더링한다.

State 변경 ↓ React가 컴포넌트 다시 실행 ↓ 새 JSX 생성 ↓ 화면 업데이트

2. useState 기본 문법

const [값, 값을바꾸는함수] = React.useState(초기값);
function Counter() {
    const [count, setCount] = React.useState(0);

    return (
        <div>
            <h1>{count}</h1>

            <button onClick={() => {
                setCount(count + 1);
            }}>
                증가
            </button>
        </div>
    );
}

3. Props와 State 차이

구분 Props State
의미 부모에게 전달받은 값 컴포넌트가 직접 관리하는 값
변경 주체 부모 컴포넌트 자기 자신
변경 방법 직접 수정하지 않음 setState 함수로 변경
렌더링 부모가 새 props를 주면 다시 렌더링 state 변경 시 다시 렌더링
한 문장 정리

Props는 밖에서 들어오는 값이고, State는 컴포넌트 안에서 바뀌는 값이다.

Chapter 07
React 렌더링 과정

1. 렌더링이란?

렌더링은 컴포넌트 함수를 실행해서 화면에 보여줄 JSX를 계산하는 과정이다.

컴포넌트 함수 실행 ↓ JSX 반환 ↓ React가 화면 구조 계산 ↓ 브라우저 화면에 반영

2. 처음 렌더링

처음 페이지가 열리면 React는 App 컴포넌트를 실행한다.

root.render(<App />) ↓ App 함수 실행 ↓ 자식 컴포넌트 실행 ↓ JSX 결과 생성 ↓ 실제 DOM 생성

3. State 변경 후 렌더링

State를 변경하는 setter 함수를 호출하면 React는 컴포넌트를 다시 실행한다.

버튼 클릭 ↓ setCount(count + 1) 실행 ↓ React가 상태 변경을 감지 ↓ 컴포넌트 함수 Counter를 다시 실행 ↓ 새 JSX 계산 ↓ 이전 화면과 새 화면 비교 ↓ 바뀐 부분만 실제 DOM에 반영

4. 컴포넌트 함수는 다시 실행된다

다음 예제에서 버튼을 누르면 콘솔에 로그가 다시 찍힌다. 이유는 state 변경으로 컴포넌트 함수가 다시 실행되기 때문이다.

function Counter() {
    const [count, setCount] = React.useState(0);

    console.log("Counter 컴포넌트 실행");

    return (
        <div>
            <h1>{count}</h1>
            <button onClick={() => setCount(count + 1)}>
                증가
            </button>
        </div>
    );
}
중요

React에서 “다시 렌더링된다”는 말은 컴포넌트 함수가 다시 실행되어 새로운 JSX를 만든다는 뜻이다.

5. setState는 즉시 변수 값을 바꾸는 함수가 아니다

setCount를 호출하면 React에게 “다음 렌더링 때 count를 새 값으로 사용해줘”라고 요청하는 것이다.

이전 값을 기준으로 업데이트할 때는 함수형 업데이트를 사용하는 것이 안전하다.

function Counter() {
    const [count, setCount] = React.useState(0);

    function increase() {
        setCount((prev) => prev + 1);
    }

    return (
        <div>
            <h1>{count}</h1>
            <button onClick={increase}>증가</button>
        </div>
    );
}

Chapter 08
일반 변수 변경과 State 변경의 차이

1. 일반 변수로 count 만들기

다음 코드는 버튼을 눌러도 화면의 숫자가 바뀌지 않는다.

function Counter() {
    let count = 0;

    function increase() {
        count = count + 1;
        console.log(count);
    }

    return (
        <div>
            <h1>{count}</h1>
            <button onClick={increase}>증가</button>
        </div>
    );
}

2. 왜 화면이 안 바뀌는가?

버튼 클릭 ↓ increase 함수 실행 ↓ count 변수 값은 변경됨 ↓ 하지만 React에게 "다시 렌더링해줘"라고 알려주지 않음 ↓ 화면은 그대로 0

일반 변수는 값이 바뀌어도 React가 알 수 없다. React가 모르면 컴포넌트를 다시 실행하지 않고, 그래서 화면도 바뀌지 않는다.

3. State를 사용하면 화면이 바뀐다

State setter를 호출하면 React가 변경을 감지하고 다시 렌더링한다.

function Counter() {
    const [count, setCount] = React.useState(0);

    return (
        <div>
            <h1>{count}</h1>

            <button onClick={() => {
                setCount(count + 1);
            }}>
                증가
            </button>
        </div>
    );
}
핵심 정리
  • 일반 변수 변경은 React에게 알려지지 않는다.
  • State setter 함수는 React에게 값 변경을 알린다.
  • React는 state 변경을 감지하면 컴포넌트를 다시 렌더링한다.
  • 화면에 보여줄 값은 일반 변수보다 state로 관리해야 한다.

Chapter 09
객체와 배열 State를 새롭게 복사하는 이유

1. 객체를 직접 수정하면 왜 문제가 되는가?

React는 state가 바뀌었는지 판단할 때 값 자체보다 참조가 바뀌었는지를 중요하게 본다.

객체 직접 수정 user.name = "김철수" 문제: 객체 안의 값은 바뀌었지만 객체 자체의 주소는 그대로일 수 있다.

2. 잘못된 예

function User() {
    const [user, setUser] = React.useState({
        name: "홍길동",
        age: 20
    });

    function changeName() {
        user.name = "김철수";
        setUser(user);
    }

    return (
        <div>
            <h1>{user.name}</h1>
            <button onClick={changeName}>이름 변경</button>
        </div>
    );
}

위 코드는 user 객체 자체를 직접 수정한 뒤 같은 객체를 다시 넣는다. 이렇게 하면 React가 변경을 제대로 감지하지 못하거나, 예측하기 어려운 코드가 된다.

3. 올바른 예

function User() {
    const [user, setUser] = React.useState({
        name: "홍길동",
        age: 20
    });

    function changeName() {
        setUser({
            ...user,
            name: "김철수"
        });
    }

    return (
        <div>
            <h1>{user.name}</h1>
            <p>{user.age}</p>
            <button onClick={changeName}>이름 변경</button>
        </div>
    );
}

{`{ ...user, name: "김철수" }`}는 기존 객체를 복사하고, name만 새 값으로 덮어쓰는 방식이다.

기존 user { name: "홍길동", age: 20 } 새 user { name: "김철수", age: 20 }

4. 왜 새 객체를 만들어야 하는가?

  • React가 state 변경을 더 쉽게 감지할 수 있다.
  • 이전 state와 다음 state를 비교하기 쉽다.
  • 컴포넌트 렌더링 결과를 예측하기 쉽다.
  • React의 최적화 방식과 잘 맞는다.
  • Redux 같은 상태 관리에서도 같은 원칙을 사용한다.

5. 중첩 객체 수정

객체 안에 객체가 있으면 안쪽 객체도 복사해야 한다.

const [user, setUser] = React.useState({
    name: "홍길동",
    address: {
        city: "서울",
        zip: "12345"
    }
});

setUser({
    ...user,
    address: {
        ...user.address,
        city: "부산"
    }
});

6. 배열 State 수정

배열도 직접 push, splice로 수정하기보다 새 배열을 만들어야 한다.

const [todos, setTodos] = React.useState([
    { id: 1, text: "React 공부" },
    { id: 2, text: "복습하기" }
]);

// 추가
setTodos([
    ...todos,
    { id: 3, text: "과제하기" }
]);

// 삭제
setTodos(todos.filter((todo) => todo.id !== 1));

// 수정
setTodos(
    todos.map((todo) =>
        todo.id === 2
            ? { ...todo, text: "Redux 공부" }
            : todo
    )
);
수업용 한 문장

React state가 객체나 배열이면 “기존 값을 직접 고치는 것”이 아니라 “새 객체나 새 배열을 만들어 교체하는 것”이 기본이다.

Chapter 10
Virtual DOM 동작 원리

1. DOM이란?

DOM은 브라우저가 HTML을 객체 구조로 표현한 것이다. JavaScript는 DOM을 이용해 화면을 변경할 수 있다.

HTML <h1>안녕하세요</h1> 브라우저가 이해하는 DOM document └── body └── h1

2. Virtual DOM을 쉽게 이해하기

Virtual DOM은 실제 DOM을 바로 고치기 전에 React가 메모리 안에서 계산하는 화면 구조라고 이해하면 된다.

정확히는 React가 JSX를 바탕으로 만든 React Element Tree를 이전 결과와 비교해서 어떤 DOM 작업이 필요한지 계산한다.

3. Virtual DOM 업데이트 흐름

1. 사용자가 버튼을 클릭한다. 2. setState가 실행된다. 3. React가 해당 컴포넌트를 다시 실행한다. 4. 컴포넌트가 새로운 React Element Tree를 만든다. 5. 이전 Tree와 새로운 Tree를 비교한다. 6. 실제로 바뀐 부분을 찾는다. 7. 필요한 DOM 작업만 브라우저에 적용한다.

4. Counter 예시로 보기

// 이전 렌더링 결과 <h1>0</h1> // setCount(1) 이후 새 렌더링 결과 <h1>1</h1> // React가 판단하는 변경점 h1 태그는 그대로이고, 안의 텍스트만 0에서 1로 바뀌었다.

React는 전체 DOM을 무조건 다시 만드는 것이 아니라, 렌더링 결과를 비교한 뒤 실제로 필요한 변경만 적용한다.

5. 렌더링 단계와 커밋 단계

단계 역할
Render 단계 컴포넌트 함수를 실행하고 새로운 화면 구조를 계산한다. 이 단계에서는 아직 실제 DOM을 바꾸지 않는다.
Reconciliation 비교 이전 렌더링 결과와 새 렌더링 결과를 비교해서 무엇이 바뀌었는지 찾는다.
Commit 단계 계산된 변경 사항을 실제 DOM에 반영한다.

6. key가 필요한 이유

배열을 렌더링할 때 React는 각 항목을 구분해야 한다. 그래서 key를 사용한다.

좋지 않은 예:

{users.map((user) => (
    <p>{user.name}</p>
))}

좋은 예:

{users.map((user) => (
    <p key={user.id}>{user.name}</p>
))}
왜 key가 중요한가?

React가 이전 목록과 새 목록을 비교할 때, 어떤 항목이 추가되었고 삭제되었고 이동했는지 판단하는 기준이 된다.

7. Virtual DOM 핵심 정리

  • State가 바뀌면 컴포넌트가 다시 실행된다.
  • 컴포넌트는 새 JSX를 반환한다.
  • React는 이전 렌더링 결과와 새 렌더링 결과를 비교한다.
  • 바뀐 부분만 실제 DOM에 반영한다.
  • 배열 렌더링에서는 비교를 돕기 위해 key가 필요하다.

실습

실습 1. Props로 상품 카드 만들기

상품명과 가격을 props로 받아 출력하는 컴포넌트를 만든다.

function ProductCard({ name, price }) {
    return (
        <div>
            <h2>{name}</h2>
            <p>{price}원</p>
        </div>
    );
}

function App() {
    return (
        <div>
            <ProductCard name="노트북" price={1200000} />
            <ProductCard name="키보드" price={80000} />
            <ProductCard name="마우스" price={30000} />
        </div>
    );
}

실습 2. State로 input 값 관리하기

입력한 값을 state에 저장하고 화면에 출력한다.

function LoginForm() {
    const [name, setName] = React.useState("");

    return (
        <div>
            <input
                value={name}
                onChange={(e) => setName(e.target.value)}
                placeholder="이름 입력"
            />

            <p>입력한 이름: {name}</p>
        </div>
    );
}

실습 3. 객체 State로 form 관리하기

name과 email을 하나의 객체 state로 관리한다.

function UserForm() {
    const [user, setUser] = React.useState({
        name: "",
        email: ""
    });

    return (
        <div>
            <input
                value={user.name}
                onChange={(e) => {
                    setUser({
                        ...user,
                        name: e.target.value
                    });
                }}
                placeholder="이름"
            />

            <input
                value={user.email}
                onChange={(e) => {
                    setUser({
                        ...user,
                        email: e.target.value
                    });
                }}
                placeholder="이메일"
            />

            <p>이름: {user.name}</p>
            <p>이메일: {user.email}</p>
        </div>
    );
}

브라우저는 JSX를 그대로 실행할 수 없으므로 Babel이 JSX를 일반 JavaScript 코드로 변환해준다.

수업 마무리 정리

  • React는 UI를 컴포넌트 단위로 만드는 JavaScript 라이브러리이다.
  • HTML에서 CDN으로 React를 간단히 실습할 수 있지만, 실제 프로젝트에서는 개발 도구를 사용한다.
  • JSX는 JavaScript 안에서 HTML처럼 작성하는 문법이다.
  • Babel은 JSX를 브라우저가 실행 가능한 JavaScript로 변환한다.
  • Props는 부모에서 자식으로 전달되는 값이다.
  • State는 컴포넌트 내부에서 관리되는 값이다.
  • State가 변경되면 React는 컴포넌트를 다시 렌더링한다.
  • 일반 변수 변경은 React에게 알려지지 않으므로 화면이 바뀌지 않는다.
  • 객체와 배열 State는 직접 수정하지 않고 새 객체, 새 배열로 만들어 변경한다.
  • Virtual DOM은 이전 렌더링 결과와 새 렌더링 결과를 비교해서 필요한 DOM 변경만 적용하는 흐름으로 이해하면 된다.
